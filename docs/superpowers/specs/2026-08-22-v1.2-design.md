# AI Relay Bench V1.2 设计说明

## 目标

将当前 AI API 测速工具升级为兼容性扫描、性能基准、跨站点对比和长期诊断平台，同时保持 Qt Widgets 桌面应用的非阻塞网络模型、三协议兼容能力和本地安全存储。

## 范围

### V1.2 纳入

1. 站点扫描向导与统一扫描结果。
2. DNS/TCP/TLS/TTFB/TTFT/生成/总耗时指标；不可观测项必须明确标记。
3. 多 Profile、多模型统一参数横向对比。
4. 原始 JSON/SSE、导出报表和扫描结果自动脱敏。
5. Mock HTTP/SSE 故障注入夹具与扩展集成测试。
6. GitHub Actions Windows 构建、测试和敏感信息扫描。

### 暂不纳入

- 真实云端监控服务。
- 自动购买或切换 API Key。
- 绕过第三方安全策略的功能。
- 强制修改服务器证书验证策略。
- 插件 ABI；协议插件化作为后续版本架构预留。

## 架构

```text
MainWindow / ScanDialog / CompareDialog
             │ 统一 ViewModel
             ▼
BenchmarkController ── ScanService ── ModelService
             │              │
             ▼              ▼
BenchmarkJob ── ProtocolAdapter ── QNetworkAccessManager
             │
             ├─ LinkTiming
             ├─ SseDecoder
             ├─ RedactionService
             └─ ResultRepository / ExportService
```

## 数据边界

- `TestResult` 增加可选 `LinkTiming`、重试/降级摘要和错误分类。
- `ScanResult` 只包含探测状态、HTTP 信息、协议能力、模型能力和诊断摘要，不保存 API Key。
- `CompareResult` 只引用脱敏后的 Profile 名称、模型名称和归一化统计。
- 原始响应在内存和导出前均经过 `RedactionService`；API Key 永不进入日志。

## 扫描流程

1. 规范化 Base URL：去除尾部 `/`，根据路径是否已有 `/v1` 生成候选端点，不重复拼接。
2. 使用当前协议认证头探测模型列表；失败时按候选路径和协议继续扫描。
3. 根据模型列表和手动模型补充详情/上下文信息。
4. 对选定模型执行最小非破坏性流式请求，探测 OpenAI、Claude、Codex 能力。
5. 分类 HTTP 错误、HTML 拦截页、JSON 错误、SSE 异常、超时和取消。
6. 输出能力矩阵与兼容性评分；评分只作为诊断参考，不代表服务质量保证。

## 链路计时

- `startedAt`：请求开始前记录。
- `firstByteMs`：首次 `readyRead` 或收到非空响应数据。
- `firstTextMs`：首个有效文本增量，即 TTFT。
- `completedAt`：最终 attempt 完成。
- DNS/TCP/TLS：若 Qt 当前平台/协议栈未提供可靠阶段信号，保留 `std::optional<double>` / `-1`，UI 显示“不可用”，禁止从总时间反推。
- 回退链所有 attempt 单独记录；总耗时包含回退成本。

## 脱敏规则

默认脱敏字段：`authorization`、`x-api-key`、`api-key`、`cookie`、`set-cookie`、`password`、`secret`、`token`、`proxy_password`。支持 JSON 对象递归处理、JSON 文本处理、SSE 文本处理和 HTTP 头处理。值保留首尾少量字符仅用于调试，短值全部替换为 `****`。

## 测试策略

- 纯函数：脱敏、URL 规范化、错误分类、评分、百分位和报告序列化用 Qt Test 单测。
- 网络集成：本地 Mock 服务覆盖跨 Chunk SSE、HTML、429/503、断流、畸形 JSON、慢响应和重试。
- UI：使用 offscreen 平台启动并验证关键窗口/语言/主题切换不崩溃。
- CI：Windows Qt 6.7+ Release 构建、CTest、打包脚本干跑和密钥扫描。

## 验收标准

- 脱敏测试覆盖 JSON、SSE、请求头、嵌套字段和导出路径。
- 新增指标不破坏已有计时定义和三协议用量归一化。
- 扫描失败必须输出可读诊断，不得导致 UI 卡死或旧结果污染新扫描。
- 多站点测试复用统一 Prompt、超时、代理和并发配置。
- 所有新增测试在本地和 CI 通过。
